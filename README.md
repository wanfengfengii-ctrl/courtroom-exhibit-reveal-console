# 双屏证物揭示台（Dual-Screen Reveal Bench）

纯前端双屏应用，用于模拟法庭的证物逐项揭示：

- **值守控制台**（`console.html`）：读取本地 JSON 证物清单，逐项发出揭示；
- **投影展示窗**（`display.html`）：由控制台打开，只呈现已应用确认的当前证物。

全部消息仅经浏览器同源的 `BroadcastChannel` 在两个浏览上下文之间传递，
**不调用任何在线服务、不发起任何网络请求**（证物 JSON 也只从本地文件/粘贴读取）。

## 要解决的问题

口头确认无法证明投影真的切换成功；迟到的确认还可能把下一项误标为已展示。
因此每次揭示都是一次严格的请求/确认握手：

1. 控制台每次揭示携带 **当前会话标识 `sessionId`** 与 **会话内严格递增序号 `seq`**；
2. 展示窗**先把内容应用到 DOM**，再回传 **同会话、同序号** 的 `ack`；
3. 控制台只有收到与当前等待项**完全匹配**的确认，才把状态标记为「投影已同步」；
4. **2 秒**无确认 → 保持「超时未确认」，允许重试；**重试使用全新序号**；
5. 旧序号 / 超时后迟到 / 重复 / 异会话的确认，一律**可观察地屏蔽**（红色状态条 + 消息记录），
   绝不把其他揭示标记为成功；
6. 展示窗未连接时，**揭示按钮禁用且状态机硬性拒绝发出揭示**；
7. 非法 JSON **整份拒绝**并清空旧证物；
8. 值守员任何时刻都只会看到**一个互斥状态**：
   就绪 / 未连接 / 等待确认 / 投影已同步 / 超时未确认 / 迟到确认已屏蔽。

## 证物 JSON 契约

根对象**仅含** `exhibits` 数组；数组长度 **1–50**；每项必须有**非空字符串**
`id`、`title`、`body`；`id` **区分大小写**且不得完全重复。

```json
{
  "exhibits": [
    { "id": "EX-01", "title": "合同书原件", "body": "第一条……" }
  ]
}
```

任何不符（语法错误、多余根字段、长度越界、字段缺失/非字符串/纯空白、id 重复）
都会导致整份拒绝，旧证物被清空，错误逐条列出。示例见 `examples/exhibits.json`。

## 消息协议（`src/core/protocol.ts`）

频道名：`reveal-bench-v1-<sessionId>`（会话标识存于控制台 localStorage，弹窗经 `?sid=` 取得）。

| 方向 | 消息 | 说明 |
| --- | --- | --- |
| 控制台→展示窗 | `ping` | 周期心跳探测 |
| 展示窗→控制台 | `hello` | 在线应答（驱动连接状态与看门狗） |
| 展示窗→控制台 | `bye` | 关闭（pagehide）告知 |
| 控制台→展示窗 | `reveal { sessionId, seq, exhibit, at }` | 揭示请求，序号严格递增 |
| 展示窗→控制台 | `ack { sessionId, seq }` | **内容应用后**回传的同序号确认 |

展示窗只接受序号更大的揭示（旧序号不能覆盖当前投影）；控制台状态机
（`src/core/machine.ts`）是纯函数，所有判定都有单元测试。

## 本地开发

```bash
npm ci
npm run dev        # http://localhost:5173 （根路径跳转 console.html）
```

打开控制台 →「打开投影展示窗」→ 粘贴或选择本地 JSON →「载入并整份校验」→ 逐项「揭示」。

## 测试

```bash
npm run typecheck  # tsc --noEmit
npm run test       # Vitest：消息状态机 + JSON 校验（17 个用例）
npm run e2e        # Playwright：两个浏览上下文端到端验收（5 个用例）
npm run verify     # 以上全部
```

Playwright 用例（`e2e/reveal.spec.ts`，同一浏览器配置内的多个浏览上下文）：

1. 未连接时禁止揭示；控制台按钮可打开展示窗并连通；
2. 合法 JSON 下逐项揭示，状态经历 等待确认 →（展示窗先上屏）→ 投影已同步，序号 `#1 #2`；
3. 吞掉 ack：内容上屏但 2 秒后超时；迟到 `#1` 确认被屏蔽；刷新恢复后重试使用 `#2` 成功，
   之后再次到达的 `#1` 旧确认仍被屏蔽；
4. 非法 JSON（语法错误与契约违反）整份拒绝并清空旧证物；
5. 关闭展示窗后控制台在看门狗周期内回到未连接。

## Docker

只提供**一个常驻 Web 组件**（静态构建 + nginx），宿主端口由 `WEB_PORT` 覆盖（默认 8080）：

```bash
WEB_PORT=9000 docker compose up --build web
# 打开 http://localhost:9000
```

一次性验收服务 `verify`（类型检查 + Vitest + Playwright，跑完即退出）：

```bash
docker compose run --rm verify
```

它在 compose 网络内通过 `E2E_BASE_URL=http://web:80` 访问 Web 组件，并以健康检查等待其就绪。
